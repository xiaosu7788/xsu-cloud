# INTEGRATIONS — xsu-cloud

外部系统清单与契约。**本文档只写「本项目与外部系统之间的那一层」**：接口形状、限流、失败处理、凭证。

分层职责与红线见 [`ARCHITECTURE.md`](ARCHITECTURE.md)；模块范围见 [`PRD.md`](PRD.md)。部署拓扑、对象存储的分桶与缓存策略在 ARCHITECTURE 第 3、7 节，本文档不重复，只链接。

**一句话原则**：外部系统是数据源，不是架构的一部分。它不出现在领域层、不出现在数据模型、不出现在技术选型里。

---

## 1. 适配器铁律

`packages/integrations/<system>/` 下每个外部系统一个目录。所有适配器必须满足：

1. **只做翻译。** 输入是本项目自有类型，输出是本项目自有类型。外部字段名（如 `b64_json`、`presign_expiry_hours`）不得出现在目录之外。
2. **不 import `packages/core`。** 适配器不知道业务规则、不知道配额、不知道谁是管理员。ESLint 强制，见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 2.2。
3. **凭证只在服务端。** 适配器从 `packages/platform` 的配置读取，绝不接受来自客户端的凭证参数。
4. **必须显式失败。** 外部错误必须映射为本项目错误码并带上下文（哪家、哪个操作、原始状态码）。禁止空 catch、禁止把失败包装成成功。
5. **必须有超时。** 每个外部调用都有明确超时，不允许无限等待。超时值写在适配器文件顶部常量，不散落。
6. **必须可被判死。** 每个集成点在 [`ARCHITECTURE.md`](ARCHITECTURE.md) 3.2 的外部依赖表里有对应行，写明「该外部系统挂掉时会发生什么」。没有这一行说明适配器没接完。

**为什么这条铁律存在**：换源的成本必须等于「加一个目录 + 改一处配置」。任何需要改领域层才能换的外部系统，说明抽象漏了。

## 3. I1 — S3 兼容对象存储

**为什么是这个形态**：只认 S3 兼容 API，不用任何厂商专用 SDK。换供应商 = 改 endpoint 与凭证，代码不动。

**契约**

- 分桶：`public`（可公开读取，走 CDN）与 `private`（一律预签名访问）。桶名与路径规范属实现细节，M4 落地时写入本节。
- 上传：`客户端 → 预签名直传 → 对象存储`，**文件不经 Node**（红线 3）。Node 只负责签发预签名 URL 与记录元数据。
- 读取：数据库只存 key 与元数据，不存 URL。URL 在读取时生成。**存 URL 等于把供应商绑进数据。**
- 预签名有效期：读取与上传的时长分别（待定，M4 落地时确定并写在此处）。

**限流**：对象存储本身不限流，但要限「签发预签名」的接口，按用户与 IP 双向限流，否则等于开放无上限上传。

**失败处理**：见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 3.2 —— 图片不可读、上传失败，但不影响已有页面渲染。上传失败必须给用户明确重试入口，不静默丢弃。

**待补**

- 桶命名、路径规范、生命周期规则（临时文件自动清理）。
- 预签名具体时长。
- 开发与生产的配置差异清单（endpoint、region、path-style 开关）。

## 4. I2 — 邮件发送（SMTP）

**为什么需要它**：账号体系选了「邮箱密码 + OAuth + 邀请码」，邮箱验证与找回密码没有 SMTP 就无法闭环。

**契约**

- 只暴露一个最小发送接口（收件人、主题、模板、变量），模板与内容属本项目，适配器只管投递。
- 开发环境固定用 Mailpit 容器，**不允许在开发环境误发真实邮件**。
- 生产 SMTP 提供方未定，选定后写入本节（含发信域名、SPF/DKIM/DMARC 状态）。

**限流**：按收件人 + 按调用来源双重限流。找回密码接口是典型的被滥用目标，必须有冷却时间。

**失败处理**：见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 3.2 —— 注册与找回流程不可用，已有会话不受影响。发送失败进队列重试，重试次数与间隔写在适配器内。

**待补**

- 生产 SMTP 提供方选型。
- 邮件模板清单（验证、找回、邀请、通知）。
- 退信处理与地址黑名单策略。

## 5. I3 — 外部生图源

**状态：未选定。** 本节先固定「无论选哪家都必须遵守的形状」，选定后补该家的具体契约。

**为什么先写形状**：生图工作台最容易出错的不是调接口，是**结果的时效性**。多数外部源的返回是预签名链接（有有效期）或带过期时间的临时任务记录，链接过期后图片就没了。**这不是某一家的问题，是这一类系统的共性。**

**契约（与具体厂家无关的强制部分）**

- **提交与查询必须用同一凭证。** 部分平台按 API Key 隔离任务，换 Key 查会直接 404。适配器内部必须自己记住「哪个凭证提交的」，不允许上层传入不同凭证。
- **结果必须立即转存。** worker 拿到结果后立刻抓取并写入本项目对象存储，`image_assets` 只存本项目自己的 key（见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 6.2）。**外部链接在系统里的生存时间不超过一次任务处理。**
- **轮询只在 worker 内。** 外部凭证到不了前端，前端只轮询本项目轻量接口（红线 2）。
- **状态机必须映射。** 外部状态到本项目 `image_jobs` 状态的映射表写在适配器内，未知状态一律映射为「失败并记录原始值」，不得猜测。
- **任务时长上限。** 必须有本项目的超时兜底，不能依赖外部源自己一定会返回终态。
- **凭证不出服务端。** 适配器不接受客户端凭证参数（铁律 3）。若未来要支持用户自带凭证，那是新的集成点，需要重新评审安全边界。

**限流**：外部源通常按账号限流。适配器必须读响应头里的限流信息并回传（如 `Retry-After`），由队列决定退避。**不要在适配器里自旋重试**，重试属队列的职责。

**失败处理**：失败必须可重试且不重复计费——提交前先落库任务记录，提交成功后才写外部任务 ID。**提交后网络中断是最坏情况**：可能已计费但没拿到 ID，此时标记为「需人工确认」，不自动重试。

**待补**

- 选定外部源，补：认证方式、提交/查询/取消的具体端点、状态枚举、限流头、结果有效期实测值。
- 该源的服务条款与合规风险（是否允许转售/中转类使用）。
- 成本计量方式（按张、按 token、按像素），用于配额计算。

## 6. I4 — 中转站外部数据源

**定位：仅数据源。** 该外部系统独立部署、独立运维，**不在本项目内**。本项目只读它的数据，不代理它的流量，不持有它的业务规则。

**边界（重要）**

- 它不出现在分层图、不进入数据模型、不影响技术选型。本条边界见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 第 1 节。
- 本项目对它的依赖是**单向且可降级**的：它挂掉，中转站页面显示明确提示，本站其他模块不受影响。
- **不复制它的业务逻辑。** 它自己的配额算法、计费规则、密钥体系属于它，本项目只展示它给出的结果，不重算。

**契约**

- 认证：管理员凭证只存服务端，用于读取聚合数据。用户的个人凭证不经过本项目的持久化层——展示即可，不留存。
- 数据方向：默认只读。**本项目不通过它写用户的余额、额度等资产数据。**若未来需要写，属于资金相关操作，必须单独评审并写入审计日志。
- 标识关联：通过 `external_identities` 表以 `(provider, external_id)` 关联，不在 `users` 上硬写外部系统 ID（见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 第 5 节）。

**限流**：本项目的读取频率必须低于该外部系统的限流上限。读到的数据进 Redis 缓存，缓存时长不得短于本项目的轮询间隔。**前端不允许直接触发对外部系统的实时查询。**

**失败处理**：见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 3.2 —— 中转站相关页面降级为提示 + 最后一次成功数据（带时间戳），不返回 500，不显示无时间戳的陈旧数字。

**待补**

- 该外部系统的实际接口清单与版本（**M4 开工前用真实凭证确认，不依赖二手调研**）。
- 它自身 API 的兼容性与升级策略（LGPL 类许可证的合规义务需在使用前确认）。
- 缓存时长与降级文案。

## 7. I5 — OAuth 提供方

**状态：已选定提供方 —— GitHub 与 Linux.do**（见 [`PRD.md`](PRD.md) 第 2 节第 9、10 项）。两家按同一形状接入，各自一个适配器目录。

**必须纠正的一个误判**：机房在境外 **不等于** 用户能稳定访问某个 OAuth 提供方。能不能用，取决于**目标用户的网络环境**，与服务器位置无关。因此 **邮箱密码必须是主路径，且在任何 OAuth 失败时都可用**。

**契约**

- 每个提供方一个适配器目录，统一映射为本项目的身份类型（外部 ID、邮箱、邮箱是否已验证、显示名、头像 URL）。
- **邮箱是否已验证（`email_verified`）必须显式处理。** 不验证邮箱就允许关联，等于开放账号接管。默认拒绝未验证邮箱的自动关联。
- **账号关联策略已定：不自动关联。** OAuth 首次登录一律创建新账号；把 OAuth 身份挂到已有账号，必须在已登录状态下由用户主动发起绑定。**不依据「邮箱相同」做任何自动合并**——这是账号被夺的主要路径。
- 所有 OAuth 回调地址与密钥只从服务端配置读取。

**限流**：登录与注册回调按 IP 限流。OAuth 回调是被扫的常见目标，失败次数要有计数与冷却。

**失败处理**：见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 3.2 —— 该登录方式不可用，邮箱密码仍可用。**不允许出现「因为 OAuth 挂了所以登不进系统」的状态。**

**待补**

- GitHub 与 Linux.do 各自的应用注册、回调地址、所需 scope（**M1 落地前用真实应用确认，不依赖二手信息**）。
- Linux.do 的 OAuth 提供方能力与限流策略需实测确认；它同时也是一个社区产品，其策略变化不受本项目控制，因此**必须能单独摘掉它而不影响其他登录方式**。
- **绑定必须有反向操作。** 用户能解除绑定；只在存在其他可用登录方式时才允许解除，避免把用户锁死在单一身份上。
- 回调域名与两家平台对回调地址的校验要求。

## 8. 凭证与配置管理

| 项 | 规则 |
| --- | --- |
| 存放 | 只放环境变量 / 服务端密钥存储，由 `packages/platform` 统一读取 |
| 前端可见 | **不允许**。构建产物中不得出现任何密钥；M4/M6 验收需实际搜索产物确认 |
| 客户端传入 | 适配器**永不**接受来自请求体的凭证参数 |
| 数据库存储 | 外部系统的用户级令牌如需持久化，必须加密存储，且明确写入 `docs/SECURITY.md`（该文件尚未创建） |
| 轮换 | 每个外部系统的密钥轮换步骤写入本节，M4 起逐个补 |
| 开发与生产 | 开发用替身（MinIO / Mailpit），**禁止开发环境配置能打到生产资源** |

**最小权限**：每个外部系统的凭证只申请该集成点真正需要的权限。对象存储的写入凭证与读取凭证能分开就分开。

**待补**：每个集成点的轮换步骤、失效检测方式（如何知道密钥被吊销了）。

## 9. 失败处理与降级通则

适用于全部集成点，具体后果见 [`ARCHITECTURE.md`](ARCHITECTURE.md) 3.2：

1. **外部失败不升级为本站故障。** 页面降级为明确提示，不返回 500。
2. **降级文案必须带时间戳。** 显示陈旧数据而不标注时间，等于骗用户。
3. **超时是默认行为。** 没有超时的外部调用视为缺陷。
4. **重试归队列，不归适配器。** 适配器只负责把「可重试」与「不可重试」区分清楚。
5. **不可重试的错误必须显式分类**，例如参数错误、余额不足、内容被拒。混在「失败」里会导致用户反复重试一件永远不会成功的事。
6. **不吞异常。** 每个失败都要留下可定位的上下文（哪个集成点、哪个操作、原始状态码、请求标识）。

## 怎么验证

- **来源单一**：本文档与 [`ARCHITECTURE.md`](ARCHITECTURE.md) 第 3 节的外部依赖表必须逐行对应。任一侧新增集成点而另一侧没有，即为缺陷。
- **适配器铁律可判定**：
  - 铁律 1 与 2 —— `pnpm lint` 必须拒绝 `packages/integrations/*` 中的 `packages/core` import；且在集成层目录外全局搜索外部字段名（如 `b64_json`）应为 0 命中。
  - 铁律 3 —— 构建产物中搜索密钥应为 0 命中；抓包确认请求体不含凭证字段。
  - 铁律 5 —— 每个适配器目录内搜索超时常量，缺一个即为缺陷。
- **降级可验证**：断开每个外部系统（改错 endpoint），确认对应页面降级为带时间戳的提示而不是 500。此项在 M4 起逐个集成点执行一次。
- **换源成本**：换掉任一外部系统的提供方，改动范围必须限于适配器目录 + 配置。超出即为抽象漏了，回到第 1 节修。
- **时效性**：到期复核本文档「状态」列，`未定` / `待决` 在对应里程碑完成后必须改掉，不允许长期挂着。
