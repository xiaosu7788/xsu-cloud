# PRD — xsu-cloud

本文件回答「做什么、不做什么、怎样算做完」。分层与边界见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，约束与红线见 [`../AGENTS.md`](../AGENTS.md)。

---

## 1. 定位

一个由单人开发与维护的个人云站，**预留对外服务能力**。

- **目标用户网络环境：待定**（见第 5 节）。这会同时影响 OAuth 选型与性能预算。
- 部署形态：单机 Docker Compose，机房在境外，无需 ICP 备案。
- 因此数据模型、配额、审计从第一天就按「会对外开放」设计，而不是先做成自用版再改。
- 本阶段**没有商业化计划**：不做多租户 SaaS，不做对外售卖。

## 2. 已锁定决策

以下决策由用户确认，实现时不得单方面偏离。理由与备选方案另记 ADR（尚未建立）。

| # | 决策项 | 选择 | 直接后果 |
| --- | --- | --- | --- |
| 1 | 站点定位 | 未来对外服务 | 每张业务表要能回答「这是谁的」；配额限流与审计日志成为前置项 |
| 2 | 账号体系 | 邮箱密码 + 第三方 OAuth + 邀请码注册 | 需要 `invites` 表与注册准入钩子；需要 OAuth 账号关联策略；**需要邮件发送基础设施** |
| 3 | 对象存储 | 需要规划 → 定为 S3 兼容 API，开发 MinIO、生产 Cloudflare R2 | 上传走预签名直传，文件不经 Node |
| 4 | 生图工作台 | **只做 UI 对接外部源**，不自托管模型推理 | 纯 TypeScript，无 GPU、无 Python；轮询下沉到 worker；结果必须转存 |
| 5 | 部署形态 | 单机 Docker Compose | 单点故障 → 备份与恢复演练是上线前置条件 |
| 6 | 移动端 | 必须适配 | 响应式原语进 M1 设计系统，不是各模块自行处理 |
| 7 | PWA | 要做 | 需要 manifest、service worker、更新策略；必做 HTTPS（已有） |
| 8 | 机房 | 境外，无需备案 | 免备案；但大陆用户的动态请求存在跨境延迟上限 |
| 9 | OAuth 提供方 | GitHub + Linux.do | 面向开发者向群体；**邮箱密码仍是主路径**，OAuth 不可用时不影响登录 |
| 10 | OAuth 账号关联 | **不自动关联**，须已登录用户主动绑定 | 杜绝「靠邮箱接管账号」路径；代价是用户需手动绑定。实现见 [`INTEGRATIONS.md`](INTEGRATIONS.md) 第 7 节 |

## 3. 模块范围

### 3.1 中转站（入口 + 控制台）

**做**

- 公开入口页：介绍与跳转到外部系统。
- 登录后的控制台：展示从外部数据源拉取的**只读**数据（用量、余额、兑换记录等）。
- 外部系统的操作入口（跳转），以及在本站内的少量聚合展示。

**不做**

- 不实现计费、号池、兑换码生成等外部系统自身的业务。
- **不把外部系统的表同步进本库**，只在本库保存必要的绑定关系与展示缓存。
- 不代理外部系统的业务请求（只读展示除外）。

**验收标准**

1. 外部数据源不可用时，控制台显示明确的降级提示，**不白屏、不返回 500**。
2. 用户 A 无法看到用户 B 的外部绑定数据（需专门测试）。
3. 外部凭证只出现在服务端，**不出现在任何客户端产物中**。
4. 死链检测：外部系统地址变更时，页面有可配置的出口，不需要改代码发布。

### 3.2 社区

**做**

- 发帖、编辑、删除、评论、点赞、标签。
- 举报与管理员审核路径。
- 列表、详情、按标签浏览、搜索。

**不做**

- 不做群聊 / 聊天室；**一对一私信**见 3.7。
- 不做富文本协同编辑。
- 不做关注流 / 推荐算法。

**验收标准**

1. 列表使用**游标分页**，连续翻页不重复、不遗漏（需测试覆盖）。
2. 重复点赞被唯一约束拦住；并发点赞不产生重复行。
3. 删除为软删除，且从列表与搜索中同时消失。
4. 举报后内容不会自动下架，必须有管理员确认路径。
5. 发文与评论受配额限制，超限返回明确错误码而非静默失败。

### 3.3 工具箱

**做**

- 工具清单、工具执行、运行历史、收藏。
- 工具执行的输入校验与结果展示。

**不做**

- 不做需要重型运行时依赖的工具（ffmpeg、OCR、浏览器自动化）。这类需求一律交 worker，且需单独立项，不在本模块默认范围内。

**验收标准**

1. 工具执行失败返回结构化错误，**不吞异常、不伪成功**。
2. 运行历史记录输入输出摘要与耗时，且**不记录敏感内容**。
3. 单用户单位时间调用次数受限，超限返回明确错误码。
4. 用户只能看到自己的运行历史。

### 3.4 生图工作台

**做**

- 任务提交、进度展示、结果画廊、参数预设。
- 结果可下载、可删除、可分享（分享范围待定，默认私有）。

**不做**

- **不自托管模型推理。** 没有 GPU、没有 Python、没有第二种语言。
- 不做批量训练的调度界面。

**关键约束（不做就会翻车的点）**

外部数据源返回的图片地址是**临时签名链接**（普遍约 24 小时过期），任务记录本身也会在失效后被清理。因此：

> worker 必须在任务成功时**立即把结果抓取并转存到本项目自己的对象存储**，应用只读自己的存储。

推论：

1. 图片存储成本由本项目承担 → 必须有配额与过期清理策略。
2. 外部凭证不能下发前端，且部分平台要求「提交与查询使用同一个凭证」→ **轮询必须放在 worker 里**。
3. 前端只轮询本项目自己的轻量接口（走 Redis 缓存），不直连外部源。

**验收标准**

1. **结果图在外部链接过期后仍然可访问**（即转存链路有效）。需要一条专门的测试，不能只测「任务成功」。
2. 任务状态机覆盖 排队 / 进行中 / 成功 / 失败 / 超时 / 取消，**不存在永久停留在「进行中」的状态**（需有超时收敛）。
3. 用户只能看到并操作自己的任务与结果。
4. 单用户的任务数与存储占用受配额限制，超限有明确提示而非静默拒绝。

### 3.5 后台管理

**做**

- 用户管理、内容管理、工具管理、任务管理、系统配置、审计日志查看。

**不做**

- 不做多租户、不做对外售卖、不做细粒度自定义角色（先用固定角色）。

**验收标准**

1. 每次敏感操作写入审计日志，含操作者、对象、时间、结果；日志**只追加不更新**。
2. 非管理员访问后台路由得到一致的拒绝响应（统一策略，不能一处 403 一处 404 一处 500）。
3. 移动端可用：表格降级为卡片，无横向滚动。

### 3.6 账号与鉴权（横切）

**做**

- 邮箱密码注册登录、第三方 OAuth、邀请码注册准入、会话管理、角色、个人资料。
- 邮箱验证、找回密码。

**不做**

- 不做企业 SSO、不做组织架构、不做多因素认证（可后续单独立项）。

**验收标准**

1. 邮箱验证、找回密码、邀请邮件可正常送达（依赖邮件集成，见 [`INTEGRATIONS.md`](INTEGRATIONS.md)）。
2. 邀请码为一次性，重复使用被拒并有明确提示。
3. **账号关联策略已确定并落地，且有测试覆盖**（策略见第 2 节决策 10：**不自动关联**，绑定须已登录后主动发起；实现契约见 [`INTEGRATIONS.md`](INTEGRATIONS.md) 第 7 节）。
4. 会话失效、退出登录、角色变更后权限立即生效。

### 3.7 站内社交（通知 / 私信 / 个人空间 / 签到 / 积分 / 成就）

可执行规格、表结构与逐条设计理由见 [`spec/SPEC-social.md`](spec/SPEC-social.md)。范围判定标准是
「只用 Postgres + Redis + 现有 worker 就能完整实现」，因此本批**不依赖任何外部系统**。

**做**

- 通知：站内消息箱、未读角标、按分类筛选；系统通知与社交通知共用一张表。
- 私信：一对一，带防骚扰的「先申请后互发」三态（`request` / `accepted` / `declined`）。
- 个人空间 `/space/[username]`：帖子、积分、成就、访问统计的展示页，分区可关。
- 每日签到：一天一次，按站点时区（UTC+8）的**日历日**；基础积分奖励。
- 积分：余额 + 流水账本，唯一入口是 `applyPoints`。
- 成就：进度每次实时算，表里只记首次解锁时间与等级；等级回落不删历史行。

**不做**

| 不做 | 为什么 |
| --- | --- |
| 排行榜 | 跨用户聚合加缓存策略是单独一批；等积分与成就落地后数据才有意义 |
| 积分商城 / 兑换出口 | 出口指向外部系统（中转站余额、订阅码），属 M4；本批只做账本 |
| 成就的物质奖励 | 参考实现的奖励是外部订阅，本站没有该外部系统 |
| 聊天室（公共房间） | 需要 WebSocket 或轮询 + 房间语义，与一对一私信不是一回事 |
| 名片 / 自定义称号 | 与空间并列的另一套展示页，各自独立 |
| 签到里程碑奖励梯度 | 梯度值需要产品决策；本批 `bonus_points` 恒为 0，列保留 |

**验收标准**

1. 一天只能签到一次：重复签到返回幂等结果而非错误，且**不重复发积分**（复合主键与幂等键各挡一层）。
2. 积分余额 = 该用户全部流水 `delta` 之和（单测对拍）。
3. 私信：无关系时只允许发一条申请；被拒后不能再发；不能给自己发。
4. 未读通知数只统计 `read = false`；同一 `dedup_key` 不产生第二行。
5. 空间页访问他人时按对方开关裁剪，关掉的分区**不下发数据**（不是 CSS 隐藏）；访问自己不受开关限制。
6. 跨用户访问在**领域层**拒绝并有测试覆盖：私信只能读自己的会话，空间展示设置只有本人能改。

## 4. 横切要求

### 4.1 移动端适配

- 所有面向用户的页面在 **360px 宽度**下可用，无横向滚动。
- 触控目标 ≥ 44px；`hover` 不得作为唯一反馈手段。
- 导航在移动端与桌面端各一套壳（侧边栏 / 底部 Tab 或抽屉），在 M1 一起做。
- 后台与列表类页面在移动端降级为卡片列表或只显示关键列。
- 生图结果画廊支持滑动手势与全屏查看。
- 使用 `dvh` 而非 `vh`；处理 `env(safe-area-inset-*)`。
- Playwright 主流程在桌面与移动两套视口各跑一遍。

### 4.2 双主题

- light / dark，跟随系统并支持手动切换，选择持久化。
- `theme-color` 随主题切换（PWA 需要）。

### 4.3 PWA

- `manifest.webmanifest`、多尺寸图标（含 maskable）、service worker。
- **更新策略必须明确定义**：静态资源内容哈希 + service worker 立即激活，或给用户「有新版本，点击刷新」的提示。不允许放任用户长期运行旧代码。
- 离线只做「提示页」，**不做离线数据**。
- 安装引导放在设置内或提示条，不做自动弹窗。

### 4.4 对外服务前置项

在对外开放之前必须具备，不是上线后补：

1. 资源归属：每张业务表能回答「这是谁的」，跨用户访问在领域层拒绝。
2. 配额与限流：注册、发帖、提交任务、上传文件。
3. 审计日志：管理员敏感操作留痕，只追加不更新。
4. 合规页面：隐私政策、用户协议、账号注销入口。**用户数据存放在境外，需在隐私政策中明确告知。**

## 怎么验证

- **范围一致性**：本文件第 3 节的「不做」清单必须与 [`ARCHITECTURE.md`](ARCHITECTURE.md) 的模块边界一致，冲突即为缺陷。
- **验收标准可执行性**：第 3 节每一条验收标准都必须能翻译成一条自动化测试或一条明确的手工检查步骤。翻译不出来的条目视为写得不好，需重写而不是跳过。
- **决策时效**：第 5 节任一项确认后，必须同时更新本文件、[`../AGENTS.md`](../AGENTS.md) 第 8 节，并补一条 ADR。

## 已知债务

- 本文件描述的系统**大部分还不存在**。第 3 节里只有 3.3 工具箱的四条验收标准经过**端到端**执行（M2，证据见 [`ROADMAP.md`](ROADMAP.md) M2「状态」与 [`spec/SPEC-tools.md`](spec/SPEC-tools.md)）；3.7 站内社交目前只有**领域层与数据层**（`packages/core/src/social` 74 例单测、迁移 `0004` 的 9 张表，见 [`DATA-MODEL.md`](DATA-MODEL.md) 3.14–3.22），其验收标准 1–6 的界面与接口一侧仍是承诺；其余模块的验收标准同样是承诺而非证据。
- 第 5 节仅剩机房位置一项待决；OAuth 提供方与账号关联策略已定（第 2 节第 9、10 项），判定规则已在 M1 落地（`packages/core/src/accounts.ts`：拒绝重复绑定、只在还有其他**可用**登录方式时允许解除，13 个单测覆盖），但**真实的 OAuth 回调与绑定流程没有跑过**（本机无提供方凭证），安全边界仍未在运行时评审过。
- 「生图工作台结果必须转存」这条约束来自对外部数据源行为的调研，**尚未在本项目的实际外部源上验证**。M6 开工前必须先用真实凭证做一次端到端确认（含签名链接的实际有效期），确认后回写本节。
- 配额的具体数值（发帖频率、任务并发、存储上限）尚未确定，需要在实际使用中定，不能拍脑袋写进文档。
